# CopyBasket v1.5.8

**Release date:** 2026-05-15
**Scope:** CI infrastructure only — binary artifacts are byte-for-byte identical to v1.5.7.

## TL;DR

If you're a user, **there is nothing new to install**. This release exists only to verify that the GitHub Actions release workflow runs cleanly after clearing two deprecation warnings. Stay on v1.5.7 (or upgrade — they produce the same files).

## What changed

The v1.5.7 release surfaced two deprecation annotations in the GitHub Actions log:

1. `softprops/action-gh-release@v2` declared Node.js 20 in its `action.yml` and was being **forced** onto Node.js 24 by an env var workaround (`FORCE_JAVASCRIPT_ACTIONS_TO_NODE24=true`).
2. `runs-on: windows-latest` will be redirected to `windows-2025-vs2026` by **2026-06-15**, with the risk that the runner image silently jumps to Visual Studio 2026 mid-stream.

Both are now addressed in `.github/workflows/release.yml`:

| Before | After | Why |
|---|---|---|
| `softprops/action-gh-release@v2` | `softprops/action-gh-release@v3` | `v3.0.0` (2026-04-12) ships Node 24 natively. No API changes — only the runtime target moved, so this is a drop-in upgrade. |
| `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24: true` | removed | All three actions in this workflow (`actions/checkout@v6`, `microsoft/setup-msbuild@v3`, `softprops/action-gh-release@v3`) now declare `node24` themselves. The workaround is obsolete. |
| `runs-on: windows-latest` | `runs-on: windows-2025-vs2026` | Explicit pin to the redirect target. Removes the redirect notice and protects future builds from silent VS-version drift. |

## Verification

The v1.5.8 workflow run completed in **1m59s** with **zero annotations** (compared to two on v1.5.7). The fix is confirmed effective for all future tag-triggered releases.
