**Release date:** 2026-07-16
**Scope:** Security & reliability hardening from a full code review. No user-facing feature changes; several latent crash, data-loss, and privilege-escalation issues are closed.

## Highlights

A code review of the whole codebase (shell extension, CB-CMT tool, NSIS installer, CI workflow) surfaced a set of hidden defects: a heap overflow reachable from Explorer, an infinite-loop / out-of-memory in the file-operation pre-scan, a DLL-unload race, a data-corrupting basket-remove path, and a `regsvr32` binary-planting vector in the installer. v1.7.0 fixes all of them. Behavior is identical for normal use — the changes are about not crashing, not corrupting, and not being exploitable in the edge cases.

---

## 🔴 Crash & memory-safety fixes

### Heap buffer overflow in `ResolveClickTarget`
`m_szFolder` is a fixed `WCHAR[MAX_PATH]`, but the navigation-pane fallback copied a `SIGDN_FILESYSPATH` string into it with unbounded `lstrcpyW`. A clicked folder whose path exceeds `MAX_PATH` (long-path-aware locations) would overflow into the adjacent `m_hMenuBitmap` member and beyond — inside `explorer.exe`. Now bounded with `lstrcpynW`.

### Infinite loop / OOM on junctions
The incident-log pre-scan (`EnumerateFilesRecursive`) recursed into any directory, including reparse points. A cyclic junction (the classic `Application Data` → `AppData\Roaming` profile loop) or a junction pointing at a huge tree turned the pre-scan into an unbounded walk → `bad_alloc` → Explorer crash, with the operation stuck "busy" forever (the thread never released its in-flight slot). Reparse points are now treated as leaves — the same rule the TreeView already used.

### DLL-unload race in the file-op thread
`FileOpThreadProc` dropped `g_cRef` and then continued executing DLL/CRT epilog code. If `CoFreeUnusedLibraries` fired in that window, the DLL could be unmapped while the epilog was still running. The thread now pins its own module with `GetModuleHandleExW` and exits via `FreeLibraryAndExitThread`, which never returns into unmapped code.

### Dangling window-class WndProc
`BasketDialog` and `SettingsDialog` registered their window classes with `GetModuleHandle(NULL)` (i.e. `explorer.exe`) and skipped `UnregisterClassW` on the `CreateWindow`-failure path. A class carrying a DLL WndProc could survive the DLL unload → crash on the next window of that class. Classes are now registered with the DLL module handle and cleaned up on every path (tracked so a concurrent dialog's class is never torn down underneath it).

## 🟠 Correctness fixes

### Basket remove: truncation + lost update
The basket viewer read each retained entry back through a `WCHAR[MAX_PATH]` buffer and rewrote the entire file with `WriteBasket`. That truncated any path longer than 259 characters, and rewriting a stale UI snapshot could drop entries a concurrent `AddFiles` had just written. The list now stores each item's full path on the heap (`lParam`) and removes exactly the selected entries via the atomic `RemoveFiles` API — no truncation, no lost update.

### Copy post-check: skip mis-reported as success
Copying into a folder that already contained a same-named file and choosing **Skip** in the conflict dialog left the destination in place — which the filesystem post-check counted as "succeeded", so the file could even be trimmed from the basket. The post-check now records each destination's pre-operation last-write time and counts a copy as successful only if the file was newly created or actually overwritten.

## 🟡 Installer & tooling security

### `regsvr32` binary-planting
The NSIS installer and CB-CMT both launched `regsvr32` by bare name. Windows resolves that by searching the *elevated* process's own directory first — for the installer, the user's download folder. A planted `regsvr32.exe` there would run with admin rights (local privilege escalation). Both now invoke the full `%SystemRoot%\System32\regsvr32.exe` path.

### Installer robustness
- The registration step now checks `regsvr32`'s exit code and aborts with a localized message instead of reporting a silent, broken install.
- Updating over a DLL that's still loaded in a running Explorer is handled by renaming the locked file aside (which works on a mapped module) and scheduling its removal with `/REBOOTOK`.
- A custom install directory restored from the registry is preserved on update instead of being forced back to `Program Files`.

## 🔵 CI hardening

- GitHub Actions pinned to commit SHAs instead of movable tags.
- `github.ref_name` routed through an `env` variable instead of being interpolated directly into a PowerShell `run` block (script-injection safe).
- A new step verifies the pushed tag matches `Version.h` and fails the build if they disagree — so a mislabeled release can't be published.

---

## ⚪ Minor robustness

Clipboard "Copy Path" now guards `GlobalLock` / `SetClipboardData` failures; `QueryContextMenu` respects the `idCmdLast` command-ID budget; basket writes `FlushFileBuffers` before the atomic rename; `DllMain` calls `DisableThreadLibraryCalls`; the `DllGetClassObject` factory no longer leaks on a QI failure; list and buttons are keyboard-tabbable; and the basket window is clamped to the monitor work area so it can't open off-screen.
